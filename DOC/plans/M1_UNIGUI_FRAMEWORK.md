# uniGUI 主框架首阶段实施与验收

> 2026-09-30。状态：主框架源码已实现，主工程编译通过；浏览器界面验收待完成。数据库和 Node-RED/FUXA 接口随后接入。详见 `../audits/M1_IMPLEMENTATION_RESULT.md`。

## 本阶段目标

在当前“组态软件”目录建立独立 uniGUI 工程，运行后打开主界面。主界面承载工程导航与模块容器，后续可加入工程配置、Node-RED 运行管理、FUXA 画面等模块，而不必重写主界面。界面应清楚区分“已有功能”和“尚未接入”，不能用空按钮冒充运行能力。

## 瀑布阶段约束与快速原型

本阶段先锁定最低验收，再快速实现可操作原型、观察实际界面并调整布局；验收通过后再进入数据库与业务配置。原型只验证导航和界面组织，不先虚构业务字段，也不连接现场服务。

| 任务 | 本期内容 | 可核查结果 |
|---|---|---|
| 工程启动 | 独立 `.dpr/.dproj`、ServerModule、MainModule、主窗体等必要文件；配置开发端口 | Delphi 工程可编译、启动，浏览器可访问 |
| 主界面 | 顶部产品与当前工程位置、左侧导航、中间内容区、基本状态区 | 首次进入可看出所在模块；切换模块不丢失界面结构 |
| 导航 | 工程、设备与 Tag、Node-RED 配置与运行、FUXA 组态与运行等入口 | 未接入模块明确显示“待实现”；无权限或失效入口不给出假成功 |
| 模块边界 | 导航与页面承载分离；业务模块以后按接口接入 | 新增一个占位模块不必改动主界面布局核心 |
| 运行反馈 | 页面加载错误和服务状态有可见反馈 | 请求失败时不空白、不显示虚假的“运行正常” |

## 不在本阶段实现

不创建正式业务数据库表，不连接生产 Node-RED 或 PLC，不部署 FUXA，不实现实际 Tag 编辑、控制和缓存转存。此阶段的“运行正常”仅指 uniGUI 框架自身能启动并提供导航，不能代表工业运行链路可用。

## 实施前需核对

1. 本机 Delphi 与 uniGUI 的安装版本、可用编译目标和许可证状态。
2. `E:\程序开发\unigui框架` 是否适合作为结构参考；读取工程与源文件后再决定借用哪些思路，不直接复制带有业务耦合的代码。
3. 主界面至少支持后续工程树、配置表格和嵌入 Web 子系统的空间分配；嵌入方式此期只预留容器，不声称 FUXA 已通过同源或身份验证。

## 完成判定

- 工程源码位于当前项目目录；可重复编译和启动。
- 浏览器中主界面可见，导航可用，未实现模块如实标示。
- 记录编译环境、启动步骤、实际界面验证结果和遗留问题。

编译成功、浏览器能打开、真实业务链路跑通是三个不同状态，逐项报告。
